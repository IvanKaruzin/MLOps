# Сценарий скринкаста ДЗ-2

Перед записью открыть терминал целиком и Excel с `docs/anatomy-worksheet.xlsx`.
Файл заполнен и проверен через пересчёт и рендер; нативное открытие в Excel/Numbers
ещё нужно проверить на машине, где установлено одно из этих приложений.

1. Показать `params.yaml`: Qwen3-1.7B, MPS, bf16, seq_len=256, batch=1.
2. Выполнить `make inspect`. Показать точное совпадение суммы параметров
   1 720 574 976, пики трёх режимов и источник `torch.mps.driver_allocated_memory`.
3. Выполнить `make check` и показать все семь зелёных пунктов без обрезки терминала.
4. Открыть `docs/anatomy.md`: условия, нулевой вклад tied lm_head,
   график, LoRA для двух конфигов, таблицу памяти и разбор четырёх дефектов.
5. В Excel показать лист «Параметры»: сумма 1 720 574 976 и контроль F18.
   В строке norm записан свод 57 векторов по 2048 и 56 по 128 элементов;
   B13=1 обозначает одну агрегированную строку. Реальное число модулей — 113.
6. На листе «LoRA» показать совпадение 1 605 632 для r=8 q/v.
   Для демонстрации второго конфига временно задать B4=16, B5=32,
   F8:F14=«да», E16=17432576: E17 должен подтвердить совпадение.
   Затем вернуть r=8, alpha=16, только q/v и E16=1605632 без сохранения временных изменений.
7. На листе «Память» показать три проверки «да» и размер весов 3281,7 МиБ.
   На листе «Ответы» пояснить, почему доля LoRA здесь 0,0933%, а не 0,192%.

Если новый `make inspect` изменил времена или пики, перенести свежие значения
в жёлтые ячейки Excel перед сдачей, чтобы файл соответствовал отчёту.
Формулы в сиреневых ячейках не менять.

В репозиторий входят отчёт, график, Excel и `uv.lock`. Видео записывается отдельно.

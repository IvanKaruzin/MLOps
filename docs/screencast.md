# Сценарии скринкастов ДЗ-3–5

Для ДЗ-5 сохранены [видео терминальной сессии](checks.mp4) и
[исходная запись событий PTY](checks-session.jsonl). Видео показывает реальное
выполнение `make check-all`, включая девять проверок ДЗ-5, финальную строку
успеха и отпечаток **06a02208c1f0**. Паузы сокращены с явной подписью в кадре;
аудио нет. JSONL сохраняет исходный вывод, временные отметки и код завершения.

Сценарии ДЗ-3–4 ниже можно использовать для отдельных демонстраций.

## ДЗ-3

Перед записью начать с чистой ветки `main` и убедиться, что рабочая версия —
`v2`, а локальный DVC remote доступен.

1. Выполнить `uv run dvc dag` и коротко показать полный граф
   `collect → clean → diversity → split → contamination`.
2. Показать воспроизводимое восстановление v1:
   `git switch --detach data-v1`, `uv run dvc checkout`, затем
   `wc -l data/raw.jsonl data/clean.jsonl data/train.jsonl data/val.jsonl data/test.jsonl`.
   В кадре должны быть объёмы `3000 → 2998 → 2397 + 300 + 301`.
3. Аналогично восстановить v2 командами `git switch --detach data-v2` и
   `uv run dvc checkout`. Показать объёмы
   `6000 → 5998 → 4800 + 599 + 599`. После демонстрации вернуться командой
   `git switch main && uv run dvc checkout`.
4. Выполнить `uv run dvc metrics diff data-v1 data-v2`. Показать реальное
   увеличение числа строк, расширение покрытия лет и языков и сохранение
   нулей контаминации. Краткая интерпретация результата находится в
   `docs/metrics-diff.md`.
5. Выполнить `make contamination` и открыть `metrics/contamination.json`.
   В кадре должны быть четыре нуля для train/test: `id_overlap`,
   `text_overlap`, `group_overlap` и `near_dup_pairs`.
6. Завершить командой `make check-hw3` и оставить в кадре финальную строку
   `Все проверки пройдены` вместе со всеми восемью зелёными разделами.

## ДЗ-4

1. На ветке `main` и версии данных v2 показать `uv run dvc dag`: стадия
   `tokenize` зависит от train/val после `split`.
2. Выполнить `make tokenize`, открыть `docs/tokenize_report.md` и
   `metrics/tokenize.json`. В текущей v2 ожидаются 4 800 train и 599 val,
   нулевая обрезка на обоих split при `max_seq_len=320` и 51 919 токенов
   train под лоссом из 576 023.
3. Выполнить `make check-hw4` без обрезки вывода. В кадре должны остаться все
   девять пронумерованных проверок, строка `Все проверки пройдены` и отпечаток
   `tests/check_hw4.sh`: **`f2002c8c9519`**.
4. Показать `git ls-files data/` (пустой результат),
   `uv run dvc status` (`Data and pipelines are up to date`) и
   `git status --short --branch` после коммита.

Если создаются отдельные видео ДЗ-3–4, ссылки на них прикладываются к сдаче
вместе со ссылкой на репозиторий.

После записи проверить, что терминал не показывает токены, ключи, абсолютные
пути с чувствительными данными или содержимое локального DVC remote. Этот
чеклист описывает порядок отдельной демонстрации ДЗ-3–4.


## ДЗ-5

Сохранённая запись `checks.mp4` показывает терминальный прогон всех проверок.
Ниже — порядок дополнительной демонстрации конфигурации, графиков и отчётов.

1. До записи выполнить `make repro`, чтобы оба полных адаптера, сравнение и
   график соответствовали текущему коду. Полное обучение в скринкаст не нужно.
2. Показать `params.yaml`: Qwen3-0.6B, собственные train/val, lr=2e-4,
   batch=8, grad_accum=1, seed=42, max_steps=null, оба варианта.
3. Показать `uv run dvc dag`: tokenize связан с train_all/train_freeze,
   compare зависит от all_layers, plot — от обоих JSON обучения.
4. Открыть `docs/curves.png`, затем `docs/compare.md`: оба train/val,
   baseline step0, пять описаний фильмов, ответы базы и адаптера.
5. Открыть раздел ДЗ-5 в `docs/defects.md` и показать фактические параметры,
   val loss, память, время и размер обоих адаптеров.
6. Выполнить `make check` без обрезки вывода. В кадре должны остаться все
   девять зелёных проверок, финальная строка «Все проверки пройдены» и
   отпечаток **06a02208c1f0**. Проверка сама запускает два коротких обучения
   и офлайн загрузку копии адаптера.
7. Выполнить `uv run python scripts/check_hw5_artifacts.py`, затем
   `git ls-files models/ data/` (пусто), `uv run dvc status` и
   `git status --short --branch` после итогового коммита.

Для сдачи приложить [видео реальной терминальной сессии](checks.mp4).
Его происхождение и успешное завершение команды зафиксированы в
[JSONL](checks-session.jsonl); сценарий выше помогает дополнительно показать
артефакты обучения.

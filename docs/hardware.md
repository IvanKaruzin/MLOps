# Аппаратный профиль и результаты бенчмарка

## Окружение

- Ноутбук: MacBook Pro
- Процессор: Apple M4 Pro
- Память: 48 ГБ unified memory
- Операционная система: macOS 26.6.2
- Архитектура: Apple Silicon, arm64
- Python: 3.12.13
- uv: 0.11.28
- PyTorch: 2.14.0
- Transformers: 5.16.1
- Accelerate: 1.14.0
- Устройство инференса: MPS (`mps:0`)
- Тип данных: `bfloat16`

Версия Python закреплена в `.python-version`, допустимый диапазон ограничен
веткой 3.12 в `pyproject.toml`, а точные версии зависимостей сохранены в
`uv.lock`.

## Выбранный профиль

Выбран профиль **Mac Apple Silicon, 16 ГБ+** и модель
`Qwen/Qwen3-1.7B`. MacBook Pro с Apple M4 Pro и 48 ГБ unified memory
соответствует этому профилю из таблицы курса. Модель работает через MPS и
занимает значительно меньше доступной памяти, поэтому переход на уменьшенную
модель не требуется. Имя модели задаётся только в `params.yaml`.

Первый инференс также проверен на базовой модели курса `Qwen/Qwen3-0.6B`.
После проверки в конфигурации оставлена модель выбранного аппаратного профиля.

## Результаты бенчмарка

Команда запуска:

```bash
make bench
```

Параметры измерения: один прогревочный запуск и три измеряемых запуска,
`max_new_tokens: 200`, `temperature: 0.0`, `seed: 42`, режим рассуждений
отключён.

| Метрика | Результат |
| --- | ---: |
| Время загрузки модели | 2.58 с |
| Скорость генерации, медиана | 42.50 tokens/sec |
| Скорость по запускам | 42.26, 42.70, 42.50 tokens/sec |
| Пиковая RSS-память процесса | 4488.1 МБ |

Медиана рассчитана корректно: после сортировки значений центральное значение
равно 42.50 tokens/sec. Разница между минимальной и максимальной скоростью
составляет около 1%, поэтому результат стабилен. Время загрузки измеряется
отдельно от генерации. Перед замерами выполняется прогрев, а до и после
измеряемых операций выполняется синхронизация MPS. RSS показывает пиковую
резидентную память всего процесса. На Apple Silicon это не отдельный объём
видеопамяти, поскольку CPU и GPU используют общую память.

## Исправленные дефекты

### 1. Имя модели было захардкожено в коде

**Проблема.** Имя `Qwen/Qwen3-0.6B` было записано строкой в нескольких Python-файлах
вместо чтения из `params.yaml`.

**Как проявлялось.** Изменение `model.name` в конфиге не меняло фактически
загруженную модель или имя в отчёте. Автоматическая подмена модели требовала бы
правок исходного кода.

**Исправление.** Загрузка модели, вывод имени и отчёт бенчмарка теперь получают
`model.name` из словаря конфигурации. В каталоге `src/` имён моделей строкой нет.

### 2. Зависимости не имели версий

**Проблема.** Прямые зависимости в `pyproject.toml` были перечислены без
ограничений версий, а воспроизводимый набор транзитивных зависимостей не был
зафиксирован.

**Как проявлялось.** Новый запуск установки мог получить другие версии
PyTorch, Transformers и остальных библиотек. Поведение проекта зависело от
даты установки и могло отличаться на другой машине или в CI.

**Исправление.** Для прямых зависимостей указаны версии, а `uv.lock` фиксирует
точные версии всего дерева зависимостей. Команда `uv sync --locked`
восстанавливает тот же набор пакетов.

### 3. Бенчмарк смешивал загрузку модели и генерацию

**Проблема.** Один таймер запускался до загрузки модели и использовался для
расчёта скорости всех последующих прогонов. Прогрев отсутствовал, а время
между измерениями накапливалось.

**Как проявлялось.** Значение tokens/sec получалось заниженным и не отражало
скорость самой генерации. Более поздние прогоны делились на всё большее
накопленное время.

**Исправление.** Время загрузки измеряется отдельным таймером. Перед сбором
метрик выполняется прогрев. Каждый измеряемый прогон использует собственный
таймер, после чего рассчитывается медиана tokens/sec. Асинхронные операции MPS
синхронизируются перед началом и после окончания замера.

### 4. Генерация не была воспроизводимой

**Проблема.** В конфигурации была задана ненулевая температура, поэтому
включался сэмплинг. Подготовленная функция фиксации seed не вызывалась перед
генерацией.

**Как проявлялось.** Два запуска с одинаковым промптом могли выдавать разные
ответы, поэтому сравнение результатов через `diff` не проходило.

**Исправление.** Температура установлена в `0.0`, что включает жадную
детерминированную декодировку. Перед загрузкой и генерацией фиксируются seed
Python, NumPy и PyTorch. Два последовательных запуска теперь дают побайтово
одинаковый вывод.

## Проверка

Штатная самопроверка запускается командой:

```bash
make check
```

Она проверяет отсутствие имени модели в Python-коде, смену модели только через
конфиг, воспроизводимость генерации, фиксацию зависимостей и корректную структуру
бенчмарка.

Проверка выполнена после подготовки отчёта: все пять пунктов завершились
успешно.

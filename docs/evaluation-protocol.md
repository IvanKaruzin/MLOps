# Протокол оценки ДЗ 6+7

Оцениваются исходная база и один готовый кандидат. Исторический короткий
sweep из шести LoRA-конфигураций завершён; текущий поиск на увеличенном
бюджете остановлен после 2 из 6 runs. Для текущей оценки пользователь явно
выбрал FINISHED run `6dc3386897fc42ec873c99937218ecb1`, прошедший loss-порог
и проверку пакета: `models:/my-qwen-adapter/6`. Этот выбор не объявляется
победой в полном новом sweep. Golden не участвует в выборе кандидата.
Условия официальной оценки и критические срезы сохранены.

## Данные и допустимые ответы

Набор `movie-genres-strict-v3` содержит 90 golden-вопросов и 5 отдельных behavioral-кейсов.
Тема — определение жанров фильма по описанию. Источник — публичный
[Pablinho/movies-dataset](https://huggingface.co/datasets/Pablinho/movies-dataset/tree/97da8cd79f0c0ee06c2f45dd30a878967d6d87a4),
ревизия `97da8cd79f0c0ee06c2f45dd30a878967d6d87a4`, лицензия CC0-1.0.

Для всех строк используется один каталог из 932 допустимых строковых меток:
931 канонический набор жанров из закреплённого CSV, включающий все
18 одиночных жанров, и отдельная метка `REFUSE`. Жанры в source-наборах
сортируются и соединяются строкой `, `. Каталог строится из источника,
а не из ответов моделей. Например, `драма, история, семейный` является
одной допустимой строковой меткой, а не тремя выбираемыми частями ответа.

Каталог взят из всего CSV. Это общий labelspace источника; он не является
train-only словарём или словарём, независимым от test. Это ограничение
оценки указано явно. Ни каталог `choices`, ни `expected`, ни source-метаданные
не передаются модели: она получает только `input` и общую system-инструкцию.

Исходные 90 `input`/`expected`, порядок, группы, срезы и 5 behavioral-кейсов
сохранены. Исправление контракта не подбирает вопросы или эталоны по ответам.
В каждой строке `expected` входит в `choices`.

Golden получен из прежнего test, вне полных train/val. По 15 фильмов
выбраны без возвращения из шести страт «до/с 2000 года × 1/2/3+ жанра»:
sample seed `20261025`, отдельный shuffle порядка `20261026`. Получены
45/45 по эпохам, 30/30/30 по числу жанров, 68/22 по длине описания.
В ячейке «до 2000, один жанр» взяты все 15 доступных фильмов. Это
сбалансированный benchmark, а не оценка естественных частот источника.

Источник, жанры и год всех 90 записей сверены с закреплённым CSV и
просмотрены AI-ассистентом. Независимая человеческая переразметка не заявляется.
В manifest сохранены три оговорки о неоднозначной или неполной source-разметке.
Они не исключаются из знаменателя после просмотра результатов.

## Генерация и scorer

Обе модели получают один prompt, chat template, `seed=20261025`,
`do_sample=false`, `enable_thinking=false` и `max_new_tokens=96`.
Точная system-инструкция находится в `evaluation/params.json`.
Baseline — Qwen/Qwen3-0.6B на закреплённой HF-ревизии. Кандидат задаётся
конкретной registry version и training run; подвижный alias не заменяет
точную спецификацию модели в отчёте.

Ответ валиден только как JSON-объект с единственным полем `answer`,
значение которого — строка из `choices`. Верность требует точного
строчного равенства `answer == expected`. Значение не нормализуется:
перестановка жанров, изменение регистра или пробелов внутри метки не
исправляются. JSON с лишними/повторяющимися ключами, неверным типом,
неизвестной меткой или пояснением вместо объекта невалиден.

Accuracy = correct/n, format rate = valid/n. Пустые, неверные и аварийные
ответы остаются в общем n и `per_item`; generation errors учитываются
отдельно. Для каждого среза сохраняются n, correct, valid, errors и доли.
Дубли, несовпадающие id и пустой набор являются ошибками входного контракта.

Полный train-index содержит 10006 вопросов: 4800 исходных и все 5206
дополнительных обучающих записей. Проверяются точные нормализованные
plot/group пересечения с train/val. Повторное кодирование
всех 4800 train и 599 val связывает исходные вопросы с настоящими
`input_ids`, `attention_mask`, `labels` тензоров; одних ID недостаточно.
Дополнительные записи кодируются отдельно с проверяемым provenance.
Exact/group проверки не исключают все смысловые перефразы, связи франшиз
и пересечения с предобучением модели.

## Критические срезы, поведение и gate

Критические срезы: `single_genre`, `three_plus_genres`, `before2000`,
`since2000`. Они покрывают простой и многометочный сценарии и обе эпохи.
Дополнительные срезы: `two_genres`, `short_description`, `long_description`;
граница длины — 400 Unicode-символов. Семейства срезов пересекаются,
поэтому их n не суммируются.

Обязательные behavioral-кейсы: формат ответа на исходном вопросе,
настоящий перефраз того же сюжета со связанными source id/group id,
отказ на географический и арифметический запросы вне темы, распознавание
анимации по описанию техники. Они считаются отдельно от golden n=90.
Отказы ожидают `REFUSE`. В текущем train есть 720 независимо от этих
кейсов составленных отказных примеров; известные пять behavioral-кейсов
и их перефразы не использовались как шаблоны для новых train-примеров.

Gate допускает кандидата только при совместимых и полных отчётах,
конечных метриках, отсутствии generation errors, общей accuracy и
format rate не ниже baseline, accuracy всех критических срезов не ниже
baseline и прохождении каждого обязательного behavioral-кейса.
Допуск ухудшения равен нулю. Missing/NaN/ошибка/несовместимость дают отказ.
Перед продвижением raw, hashes и метрики перепроверяются.

Сохранены также заранее заданные дополнительные условия: общие micro-F1
и macro-F1 и micro-F1 критических срезов не ниже baseline. Они строже
обязательного минимума задания, дополняют accuracy/format/behavioral
и не ослаблялись после просмотра ответов.

Отрицательная проверка портит отдельную копию ответов; она должна получить
отказ, сохранив исходные raw, веса и aliases. `make promote` разрешён только
после PASS. Отказ по качеству допустим: candidate остаётся доступным,
champion не назначается и baseline автоматически не обновляется.

## Артефакты и доступ

`eval-data.dvc` отслеживает `data/eval`. Переносимый текстовый архив
`docs/datasets/hw67-evaluation.tar.gz` размером 3521457 байт содержит шесть
текстовых файлов: golden, behavioral, полный train-index из 10006 строк, manifest,
`auxiliary.json` и отдельный `improvement-holdout.jsonl`.
Веса и тензоры в архив не входят.

- SHA256 архива: `5bdeace9dab2e12089ba41f923c657a93e1305f7d2c6c83c7e8d8a098481dd0e`.
- SHA256 manifest: `f81c5ae3c7e8b5c3a75eea6ca4c2b0aeb47a5ad903284469141649c57994e73a`.
- SHA256 auxiliary: `0af9efde4dfb2665459f4f0161c5542d72872e71ac8a673195fd903e014c8785`.
- SHA256 закрытого holdout: `4d9f9231d7b46927d60df8b8a2f55f89b27ad7223bc54442f4028a33fbc477fc`.

```bash
tar -xzf docs/datasets/hw67-evaluation.tar.gz
uv run dvc status eval-data.dvc
```

Для проверки candidate6 достаточно восстановления архива/DVC. Следующие
команды относятся к отдельной пересборке из исходного CSV и тензоров
с новой provenance-ревизией, а не к точному восстановлению frozen input:

```bash
uv run python scripts/prepare_hw67_auxiliary.py
make prepare-eval
```

Первый скрипт воспроизводит train/dev bundle и проверяет неизменные dev
и байты закрытого holdout, не перезаписывая holdout. Второй использует
bundle для полного training-index и переносимого архива. Trainer читает
только train/dev из bundle и не открывает `improvement-holdout.jsonl`.

Точный frozen input восстанавливается из архива/DVC; соответствующий генератор
сохранён в parent MLflow run, `data-preparation/`. Rebuild последним builder
после изменения кода создаёт новый provenance SHA, даже при тех же строках.

Сырые ответы, per-item результаты, diff и решения gate сохраняются в MLflow
и `metrics/`. После использования golden для разработки его нельзя
называть независимым итоговым аудитом. Сходство слов и модель-судья не
заменяют scorer; judge и платный API для этой сдачи не используются.

## Улучшение модели перед ДЗ 8–10

Дополнительные инженерные критерии первоначально зафиксированы до проверки
результатов нового обучения. Изменение одного порога после просмотра DEV
отдельно описано ниже. Официальные 90 golden-вопросов, пять behavioral,
932 choices, baseline, system, лимит 96 и прежний gate остаются неизменными.

Текущий бюджет обучения — одна полная эпоха, 2502 шага с `batch=4` и
`grad_accum=1`. Train содержит 10006 записей: исходные 4800, 2758
дополнительных фильмов из закреплённого CSV, 1728 авторских жанровых
примеров и 720 отказов. Для выбора checkpoint используется только NLL
исходного val599. Полный валидационный пул из 1087 записей включает эти 599 и
488 записей дополнительного dev: 344 новых исходных фильма, 96 отказов и 48 жанровых
примеров. Синтетические жанровые примеры и отказы в каждом разбиении
поровну представлены на английском и русском языках.

Ревизия `movie-genre-auxiliary-v2-dev-informed` спроектирована с учётом
ошибок на dev. Сам builder не читает model outputs; source-отбор остаётся
независимым от них, но дизайн train-augmentation является dev-informed.
Прежние train-строки и все dev-строки сохранены. В добавленных 1488
жанровых строках — 248 консервативно объединённых парных двуязычных групп,
496 языковых premises и по три представления каждого. Пары могут быть
переводами или менять детали сюжета; они не выдаются за статистически
независимые истории. Повторяемые описания формы/тона являются учебными
признаками авторских примеров, а не естественными source-синопсисами.

Закрытый holdout из 541 записи зафиксирован до обучения и ещё не использовался для
инференса: 325 новых исходных фильмов, 144 отказа и 72 жанровых примера.
Для 48 отказов авторские категории задач отсутствуют в train/dev; это не
доказательство полной смысловой независимости областей. Дополнительные
записи разделены по source ID, описаниям и семействам синтетических
формулировок. Дополнительные source-фильмы наследуют прежнюю роль года
выпуска (train/val/test) и также не пересекаются по
нормализованным названиям с raw6000 и между ролями; это не исключает все
связи франшиз. Исходные данные не переписываются; полный training-index
дополнен всеми новыми обучающими записями.

Development-критерии проверяются отдельно: source micro-F1≥0.50,
macro-F1≥0.35, accuracy≥0.10; accuracy синтетических жанров≥0.75;
accuracy отказов≥0.95; format rate жанров и отказов≥0.90;
ложные отказы на жанровых запросах≤0.02, включая русскоязычные отдельно.
Ни одна ошибка генерации не исключается из знаменателя.

После выбора единственного победителя по исходному val599 и завершения
сопоставимого поиска закрытый holdout проверяется один раз. Для исходных
фильмов нужны micro-F1≥0.50, macro-F1≥0.35 и прирост не менее 0.05
по micro-F1, macro-F1 и accuracy относительно прежней v5 на ЭТОМ ЖЕ наборе.
Accuracy синтетических жанров≥0.75, отказов≥0.95, отказов на новых темах≥0.90;
format rate жанров и отказов≥0.90, ложные отказы≤0.02 также на русском.
Ошибки генерации любой сравниваемой модели закрывают дополнительную проверку.

**Изменение 2026-11-02 после просмотра DEV.** По явной просьбе пользователя
порог `synthetic_genre_accuracy` снижен с **0.80 до 0.75** одновременно
для DEV и будущей проверки закрытого holdout. Наблюдаемые **37/48 = 0.770833**

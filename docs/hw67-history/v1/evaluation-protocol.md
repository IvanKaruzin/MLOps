# Протокол оценки ДЗ 6+7: movie-genres-mcq-v1

Протокол задан до получения ответов baseline и candidate. Состав вопросов,
срезы, decoding и правило допуска не меняются после просмотра результатов.

## Задача и источник разметки

ДЗ 3–5 обучает многометочную классификацию жанров по англоязычному описанию
фильма. Для машинной проверки ДЗ 6+7 задача преобразована в MCQ: выбрать один
из четырёх полных наборов жанров. Русские названия жанров взяты из той же
таксономии, что в SFT. Все четыре варианта имеют одинаковое число жанров;
каждый неверный вариант заменяет одну исходную метку другой. Позиция верного
ответа сбалансирована: по 15 ответов A/B/C/D. Модель получает описание и все
варианты; отдельное поле `expected` и исходная разметка ей не передаются.

Источник: публичный [Pablinho/movies-dataset](https://huggingface.co/datasets/Pablinho/movies-dataset/tree/97da8cd79f0c0ee06c2f45dd30a878967d6d87a4),
ревизия `97da8cd79f0c0ee06c2f45dd30a878967d6d87a4`, лицензия CC0-1.0.
Используется собственный выход `data/test.jsonl` стадии split ДЗ 3.
Сначала выполнено разделение исходных групп `release_year`, затем построен
golden; источники train и val исключены целыми группами.

Golden содержит 60 разных фильмов. В каждой группе сложности по числу меток
выбираются 20 минимальных SHA256 от версии протокола и source id. Отбор
не использует ответы модели, loss или известность фильма. Преобразование
сохраняет source id, описание, жанры, варианты, ожидаемую букву и SHA256
исходной записи в `data/eval/manifest.json`. Проверки подтверждают точное
соответствие верного варианта исходной разметке, единственность вариантов,
одинаковую мощность наборов и отсутствие пересечений источников.

Дополнительно исходные описания всех 60 выбранных фильмов сравниваются
с полными исходными описаниями train и val после casefold и свёртки пробелов.
Префикс вопроса MCQ и варианты в этой проверке не участвуют: они могли бы
скрыть точное совпадение plot. Обнаружено 0 пересечений с 4800 train
и 0 с 599 val; результат записан в `manifest.source_plot_leakage`.

При просмотре исходных описаний до генерации исключены две записи:
`movie_88c6628229ecf1533a1546fc79ad18165467c2b848bb70e13c38f90990ee3a44`
прямо называет фильм романтической комедией, тогда как source пропускает
комедию; `movie_00a04214fa9e6059ab2953acb5ab5af37715ba0e64e7a709037a53e237aabf2c`
содержит плохо отредактированное описание с нарушенными связями между
персонажами. Исключения сохранены в коде/manifest и не связаны с ответами
моделей. Вместо них взяты следующие записи по тому же SHA256-порядку.

Разметка проверена на соответствие закреплённому источнику, а не объявлена
независимо проверенной человеком. Жанры субъективны, могут быть неполными
и не всегда однозначно следуют из короткого описания. Поэтому измеряется
согласие с данной таксономией в заданном MCQ, а не абсолютная истинность
жанров и не полное качество свободной многометочной генерации.

## Срезы и правило допуска

До генерации закреплены следующие группы:

| Срез | Определение | Назначение | Критический |
|---|---|---|---|
| `single_genre` | Одна исходная жанровая метка, n=20 | Базовая способность различать жанры | Да |
| `two_genres` | Две исходные метки, n=20 | Составная классификация | Нет |
| `three_plus_genres` | Три и более исходных меток, n=20 | Основной многометочный сценарий SFT | Да |
| `short_description` | Описание не длиннее 400 Unicode-символов | Проверка ограниченного контекста | Нет |
| `long_description` | Описание длиннее 400 Unicode-символов | Проверка длинного контекста | Нет |

Первые три среза не пересекаются и дают n=60. Срезы длины пересекаются
с ними: суммировать все размеры для получения общего n нельзя.

Допуск ухудшения равен нулю. Candidate проходит только при совместимых
и полных отчётах, отсутствии ошибок генерации, общей accuracy и format rate
не ниже baseline, accuracy обоих критических срезов не ниже baseline
и прохождении каждого обязательного behavioral-кейса. Missing, NaN,
ошибка генерации, несовместимость или регрессия означают отказ. Нельзя
после результатов исключить вопрос, сменить срез или ослабить порог.

## Общий протокол генерации и scorer

Точная system-инструкция хранится в `evaluation/params.json`: жанры фильмов
по описанию, один JSON с единственным строковым `answer`; для запросов
вне этой задачи — `{"answer":"REFUSE"}`. Обе версии получают одинаковые
system/user сообщения, chat template, `enable_thinking=false`, `seed=42`,
`do_sample=false`, `max_new_tokens=32`. Нормализация ответа и извлечение
метки из пояснений не допускаются.

Впервые baseline — исходная Qwen/Qwen3-0.6B на конкретной HF-ревизии,
закреплённой `baseline-init`. Candidate — конкретная версия реестра,
выбранная только по общему validation loss шести runs. Golden не используется
для ранжирования этих шести моделей. Полная генерация выполняется только
для baseline и одного candidate. Точные модели и SHA256 протокола/данных
сохраняются в отчётах; baseline не меняется автоматически.

Ответ валиден только как JSON-объект с единственным полем `answer`, строкой
из разрешённых `choices`. Правильность дополнительно требует совпадения
с `expected`. Невалидный, пустой, оборванный и аварийный ответ дают 0,
остаются в общем знаменателе и `per_item`. Accuracy = correct/n;
format rate = valid/n; generation errors учитываются отдельно. В каждом
срезе сохраняются n, correct, valid, errors и обе доли.

## Обязательное поведение

Четыре кейса заданы до оценки и считаются отдельно от n=60:

| ID | Тип | Ожидаемое свойство |
|---|---|---|
| `behavior-format` | format | Решить golden-пример про haunted house с явным указанием ужасов и выдать строгий JSON |
| `behavior-paraphrase` | paraphrase | То же описание и group_id; инструкция перефразирована, варианты циклически переставлены, правильная буква изменена; `paired_with=behavior-format` |
| `behavior-refusal` | refusal | На вопрос о столице Франции ответить REFUSE, соблюдая границу «только жанры фильмов» |
| `behavior-format-known` | format | Определить анимацию по явному описанию покадрово нарисованных персонажей и выдать строгий JSON |

Пара format/paraphrase использует один фильм; её нельзя считать двумя
независимыми наблюдениями качества. Даже при росте средней accuracy
непрохождение любого обязательного кейса запрещает champion.

## Связь с обучением, версии и доступ преподавателю

`scripts/prepare_hw67_eval.py` экспортирует все 4800 исходных train-вопросов
в `training-index.jsonl` и проверяет train/val по всем исходным записям:
повторная токенизация должна точно совпасть с `id`, `input_ids`,
`attention_mask` и `labels` сохранённых `.pt`. Проверка не заменяет тензоры
текстовым сравнением. SHA256 исходных файлов, тензоров и порядок id записаны
в manifest. Код и настройки токенизации находятся в DVC DAG `tokenize`.

Набор отслеживается `eval-data.dvc`. Маленький текстовый архив
`docs/datasets/hw67-evaluation.tar.gz` включён в Git, поэтому преподавателю
не нужны частные credentials или авторский DVC cache для чтения набора.
Архив содержит только golden, behavioral, полный training-index и manifest;
весов и тензоров в нём нет.

Для восстановления файлов из клона:

```bash
tar -xzf docs/datasets/hw67-evaluation.tar.gz
uv run dvc status eval-data.dvc
```

Для повторного построения при уже восстановленных исходных split и `.pt`:

```bash
HF_HUB_OFFLINE=1 uv run python scripts/prepare_hw67_eval.py
uv run dvc status eval-data.dvc
```

Архив имеет детерминированные метаданные и должен воспроизводиться побайтно.
Локальный DVC remote проекта — `dvc_remote` внутри checkout; он удобен
для работы на авторской машине, но сам по себе не даёт доступа через GitHub.
Переносимый текстовый архив решает доступ именно для данных оценки.

## Ограничения вывода

Golden из бывшего test становится набором регрессионной разработки и больше
не является независимым финальным аудитом. 60 вопросов и сбалансированная
выборка не дают точной оценки качества на всем распределении фильмов.
Совпадения текста и групп проверяются автоматически; смысловые перефразы,
связи фильмов одной франшизы и пересечение с предобучением этим не исключены.
Новая JSON/MCQ инструкция отличается от свободного перечисления жанров SFT;
протокол отдельно показывает format rate, чтобы не скрыть этот эффект.
При отказе candidate остаётся доступным; baseline и champion не подменяются.

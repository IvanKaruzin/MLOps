# Протокол ДЗ 6+7: свободная классификация жанров, v2

Версия набора — `movie-genres-free-v2`. Этот протокол, набор, критические
срезы и лимит ответа фиксируются до генерации v2. Предыдущая оценка v1
с вариантами A–D сохранена в `docs/hw67-history/v1` и
`metrics/hw67-history/v1`; её результаты не являются результатами v2.

## Содержательная задача и исходные данные

Модель получает только англоязычное описание фильма и общую инструкцию:
свободно назвать все применимые жанры. Готовых наборов жанров, вариантов
A–D и правильного ответа в пользовательском prompt нет. Это возвращает
оценку к задаче многометочной классификации ДЗ 3–5. В общей system-инструкции
перечислены 18 допустимых жанров из исходной таксономии. Этот словарь
одинаков для всех моделей и не подсказывает комбинацию конкретного фильма.

Источник — [Pablinho/movies-dataset](https://huggingface.co/datasets/Pablinho/movies-dataset/tree/97da8cd79f0c0ee06c2f45dd30a878967d6d87a4),
ревизия `97da8cd79f0c0ee06c2f45dd30a878967d6d87a4`, лицензия CC0-1.0.
Используется прежний test из ДЗ 3: 599 записей. Train 4800 и val 599
не переразбиваются; их исходные файлы и тензоры сохраняются.

Отбор v2 не читает ответы моделей или loss. Сохраняются только два
исключения качества источника, установленные ещё до генерации v1:

- `movie_88c6628229ecf1533a1546fc79ad18165467c2b848bb70e13c38f90990ee3a44`:
  описание прямо называет фильм романтической комедией, а source не содержит
  комедию в разметке;
- `movie_00a04214fa9e6059ab2953acb5ab5af37715ba0e64e7a709037a53e237aabf2c`:
  плохо отредактированное описание с нарушенными связями между персонажами.

Обе записи относятся к 2011 году и имеют две source-метки. Остальные
597 записей составляют допустимый пул. Новые исключения по результатам
модели, неудачным жанрам или сложным ответам не вводятся.

## Случайная стратифицированная выборка

Из пула выбираются 90 разных фильмов без возвращения: по 15 из каждой
ячейки «эпоха выпуска × число исходных жанров». Пул внутри каждой ячейки
сначала сортируется по source id, затем перемешивается одним
`random.Random(20261025)` в зафиксированном порядке ячеек. Берутся первые
15 строк. Финальный порядок 90 вопросов перемешивается отдельным
`random.Random(20261026)`. Это воспроизводимая случайная выборка внутри
заданных ячеек, а не первые строки и не отбор минимальных хешей.

| Ячейка | Доступно в пуле | Выбрано |
|---|---:|---:|
| `before2000__single_genre` | 15 | 15 |
| `before2000__two_genres` | 31 | 15 |
| `before2000__three_plus_genres` | 51 | 15 |
| `since2000__single_genre` | 90 | 15 |
| `since2000__two_genres` | 155 | 15 |
| `since2000__three_plus_genres` | 255 | 15 |

В ячейке «до 2000, один жанр» взяты все 15 доступных фильмов: это перепись
ячейки, хотя порядок также перемешан. Итог сбалансирован по эпохам
и числу меток, но не по отдельным годам или каждому жанру. Поддержка
жанров, годов, ячеек и конкретные selected source id сохранены в manifest.
Нельзя называть эту accuracy оценкой естественной распространённости
жанров в исходном test: балансировка меняет веса популяции.

## Разметка и проверка источника

Каждая строка имеет `task=multilabel`, исходное описание в `input`, полный
набор допустимых жанров плюс `REFUSE` в `choices` и канонически
отсортированную строку жанров через запятую в `expected`. Поля `source_id`,
`release_year`, `stratum`, `group_id`, `source` и `slices` сохраняют
происхождение. Модель видит только `input` и общую system-инструкцию;
`expected`, `choices`, source-метаданные и срезы в prompt не добавляются.

AI-ассистент просмотрела все 90 выбранных описаний и исходных меток
до генерации. Код дополнительно повторно читает закреплённый CSV
и проверяет точное равенство описания, множества жанров и года для каждой
из 90 строк. Это проверка связи с источником, а не независимая человеческая
переразметка. Source может быть неполным и субъективным. Например, у фильма
с путешествием во времени source может не содержать фэнтези/фантастику,
а краткое описание документального фильма может не объяснять его форму.
Такие ограничения явно сохранены в review notes, без подмены разметки.

| Golden ID | Source-метки | Ограничение описания |
|---|---|---|
| `movie-free-011` | документальный | Synopsis рассказывает о Scream, не объясняя прямо, что оцениваемый фильм документальный |
| `movie-free-012` | анимация, мелодрама | В сюжете есть путешествие во времени, но source не содержит фантастику/фэнтези |
| `movie-free-048` | драма | Исторический сюжет об агенте и публичном доме не позволяет однозначно восстановить тональность по единственной source-метке |

Эти записи остались в случайной выборке. Флаги помогают разбирать ошибки,
не исключают строки из метрик и не меняют source-эталон после генерации.

## Срезы, метрики и правило допуска

До ответов заданы четыре критических среза: `single_genre`,
`three_plus_genres`, `before2000`, `since2000`. Они проверяют базовый
однометочный сценарий, сложную многометочную задачу и обе эпохи.
`two_genres` и длина описания — дополнительные срезы. Граница длины:
400 Unicode-символов; длинное описание имеет более 400 символов.

Эпохи дают 45/45, число меток — 30/30/30. Эти семейства пересекаются:
суммировать все размеры срезов для получения общего n нельзя. Размеры
коротких/длинных описаний и support отдельных жанров берутся из manifest
и показываются вместе с фактическими counts.

В выбранном наборе 68 коротких и 22 длинных описания. По годам:

Меток больше 90, потому что задача многометочная. Выборка остаётся
неравномерной по отдельным жанрам: для вестерна и музыки всего по одному
фильму, поэтому их результаты не дают устойчивой оценки качества.

Основная accuracy — exact-set accuracy: валидное множество предсказанных
жанров должно полностью совпасть с source-множеством. Format rate считается
отдельно. Для содержательного разбора дополнительно считаются TP/FP/FN,
micro-F1 и macro-F1. Macro усредняет все 18 жанров, включая жанры с нулевой
поддержкой; `zero_division=0`. Жанры с n=0 не скрываются. Невалидный ответ
даёт пустое множество предсказаний, сохраняет все FN и остаётся
в знаменателе; форматная ошибка не превращается в пропущенный вопрос.

Допуск ухудшения равен нулю: общие exact-set accuracy, format rate,
micro-F1 и macro-F1 кандидата не ниже baseline. В каждом из четырёх
критических срезов exact-set accuracy и micro-F1 не ниже baseline.
Все пять обязательных behavioral-кейсов кандидата должны быть пройдены.
F1 дополнительно проверяет частично правильные жанры и не отменяет
требования к exact-set accuracy.
Missing, NaN, ошибка генерации, неполный или несовместимый отчёт означают
отказ. Порог, критические срезы и вопросы после ответов не меняются.

## Единый контракт генерации

Точная инструкция и настройки находятся в `evaluation/params.json`:
`seed=20261025`, `do_sample=false`, `enable_thinking=false`,
`max_new_tokens=96`. Все сравниваемые модели получают один prompt, словарь,
chat template и decoding; конкретные модели закрепляются отдельными
спецификациями. Четыре роли — `baseline`, `previous`, `candidate`,
`sampling_control`. Дополнительные ранее обученные модели перечислены
в `evaluation/comparison-models.json`; они оцениваются на тех же вопросах.
Выбранный candidate остаётся выбранным по validation loss, а не по golden.

Ответ — строгий JSON с единственным полем `answer`, строкой жанров через
запятую. Порядок жанров, регистр и окружающие пробелы не меняют множество.
Алиасы, перевод с другого языка и домысливание меток не допускаются.
Повтор жанра, неизвестная метка, лишнее поле JSON, пояснение, Markdown,
неверный тип, NaN, дубликат JSON-ключа и смесь REFUSE с жанрами невалидны.
Отказ `REFUSE` — отдельный атомарный ответ. Для обычного фильма он валиден
по форме, но неверен по содержанию; для запроса вне задачи — ожидаемый отказ.
Пустой ответ не равен правильному отказу.

Сохраняются сырые ответы всех версий, per-item множества и ошибки,
counts/метрики срезов, списки исправленных/потерянных вопросов и MLflow run.
Версии протокола, набора и baseline связываются SHA256. Перед gate/release
метрики пересчитываются из raw. Baseline не меняется автоматически.

## Обязательные behavioral-кейсы

Пять заранее заданных кейсов имеют отдельный знаменатель:

| ID | Проверка |
|---|---|
| `behavior-format` | Исходный golden-пример о Джеде Купере: свободно определить жанр в строгом JSON |
| `behavior-paraphrase` | Само описание сюжета переписано другими словами; сохранены попытка линчевания, возвращение к работе законника, девять виновных и Дикий Запад; тот же source id/group id и `paired_with=behavior-format` |
| `behavior-refusal-geography` | На вопрос о столице Франции вернуть REFUSE |
| `behavior-refusal-arithmetic` | На просьбу вычислить произведение вернуть REFUSE |
| `behavior-format-known` | Определить анимацию по явному описанию покадрово нарисованных фигур |

Перефраз меняет реальный plot, а не только вопрос-инструкцию и не порядок
готовых ответов. Связанные кейсы одного фильма не являются независимыми
статистическими наблюдениями и не увеличивают golden n=90. В train
не добавлялись вспомогательные JSON/refusal-примеры: требование отказа
не обучалось отдельной целью и может честно не пройти.

## Контроль утечки и связь с тензорами

Исходные split разделены целыми группами `release_year`. Проверяются
непересечение id и групп train/val/test, а также совпадения исходных
описаний всех evaluation-кейсов с полными train и val после casefold
и свёртки пробелов. Сравниваются сами plot без MCQ-обёрток. Должно быть
0 пересечений с 4800 train и 0 с 599 val. Source proof сохраняется в manifest.
Эта проверка не гарантирует отсутствия всех смысловых перефразов,
связей фильмов одной франшизы или пересечения с предобучением модели.

`training-index.jsonl` содержит все 4800 исходных train-вопросов. При
подготовке повторно токенизируются все 4800 train и 599 val записей;
`id`, `input_ids`, `attention_mask`, `labels` должны точно совпасть
с сохранёнными `.pt`. SHA256 исходников, тензоров и порядка id находятся
в manifest. Проверка читает тензоры, не переписывает их и не меняет train.

## Версионирование и доступ

`scripts/prepare_hw67_eval_v2.py` строит набор и evidence; `eval-data.dvc`
отслеживает `data/eval`. В Git включён переносимый текстовый архив
`docs/datasets/hw67-evaluation.tar.gz`: golden, behavioral, полный
training-index и manifest. В нём нет весов или тензоров; преподавателю
не нужен доступ к частному DVC cache для чтения вопросов и проверки кода.
Локальный remote `dvc_remote` сам по себе не публикует данные через GitHub.

Восстановление из клона:

```bash
tar -xzf docs/datasets/hw67-evaluation.tar.gz
uv run dvc status eval-data.dvc
```

Повторное построение при восстановленных исходных split и тензорах:

```bash
HF_HUB_OFFLINE=1 uv run python scripts/prepare_hw67_eval_v2.py
uv run dvc status eval-data.dvc
```

Архив имеет детерминированные метаданные и воспроизводится побайтно.
После применения test для повторной разработки golden нельзя называть
независимым итоговым аудитом. Небольшая сбалансированная выборка и source
разметка ограничивают вывод даже при росте F1. Отказ качества — допустимый
итог: candidate доступен, baseline и champion остаются прежними.

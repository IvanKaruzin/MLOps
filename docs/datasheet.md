# Datasheet: описания фильмов и жанры

## Статус и тема

Тема ДЗ-3: «Определение жанров фильма по его текстовому описанию». Тема выбрана
для реализации, но внешнее подтверждение преподавателя о том, что она свободна,
ещё не получено. На этом локальном этапе сообщения преподавателю не отправлялись.
До подтверждения набор считается черновиком и не готов к сдаче.

Задача — многометочная классификация: модель получает только описание фильма и
возвращает одну или несколько канонических жанровых меток. Название фильма не
входит в пользовательский prompt, чтобы модель не могла решить задачу простым
воспоминанием известного названия.

## Выбор источника

Приоритетные официальные API не используются в текущей версии:

- IMDb API через AWS Data Exchange требует отдельной подписки, API key и
  подтверждения права сохранять учебную локальную выборку. Наличие этих прав и
  доступ к полям `plot`/`description` и `genres` локально не подтверждены;
  секреты и переменные окружения не проверялись. Бесплатные
  [IMDb Non-Commercial Datasets](https://developer.imdb.com/non-commercial-datasets/)
  не содержат описаний и потому не подходят как единственный источник.
- Публичная официальная документация договорного API Кинопоиска с описаниями и
  жанрами не подтверждена. Страницы Кинопоиска не скрейпятся, сторонний
  `kinopoisk.dev` не используется.

Зафиксированный fallback —
[`Pablinho/movies-dataset`](https://huggingface.co/datasets/Pablinho/movies-dataset)
на Hugging Face:

| Параметр | Значение |
|---|---|
| Ревизия | `97da8cd79f0c0ee06c2f45dd30a878967d6d87a4` |
| Файл | `9000plus.csv` |
| SHA-256 файла | `1d7636cc8ff75be70c0c00daaf5371242913dd29d17ac96417cf64ed4f581a6f` |
| Строк по карточке | 9 837 |
| Поля | `Release_Date`, `Title`, `Overview`, `Original_Language`, `Genre` |
| Дата получения метаданных карточки | 2026-09-21 |
| Лицензия | [CC0-1.0](https://creativecommons.org/publicdomain/zero/1.0/) |
| Зафиксированный файл | [snapshot по commit hash](https://huggingface.co/datasets/Pablinho/movies-dataset/resolve/97da8cd79f0c0ee06c2f45dd30a878967d6d87a4/9000plus.csv) |

Карточка утверждает, что набор перенесён из
[исходного набора Kaggle](https://www.kaggle.com/datasets/disham993/9000-movies-dataset/data)
и опубликован автором исходного набора под CC0-1.0. Лицензия разрешает
копирование, изменение и распространение без запроса разрешения. В проекте
сохраняются ссылка, полный commit hash и дата проверки; источник скачивается
один раз в `sources/movies-dataset/9000plus.csv` и далее версионируется DVC.
Сам CSV в Git не добавляется: каталог сохранён через
`sources/movies-dataset.dvc`, а collect дополнительно проверяет SHA-256 перед
чтением. Если локального файла нет, `huggingface_hub` скачивает только
`9000plus.csv` ровно с указанной ревизии во временный cache.

Ограничение: в snapshot нет отдельного поля `title_type`. Карточка позиционирует
строки как фильмы, но это не даёт построчной независимой проверки типа. Поэтому
метка `TV Movie` исключается как неоднозначный формат, а отсутствие сериалов и
эпизодов дополнительно проверяется выборочно до публикации версий. Если такая
проверка обнаружит не-фильмы, нужен источник с устойчивым идентификатором и
явным типом; присваивать `movie` вопреки данным нельзя.

## Собственная переработка

Исходный CSV не является готовой сдачей. Детерминированное преобразование
зафиксировано в `params.yaml` и включает следующие шаги:

1. Проверить наличие обязательных колонок и отбросить строки с пустыми
   `Overview`, `Genre`, `Title`, некорректной датой или языком.
2. Нормализовать Unicode и пробелы. Разобрать `Genre` по запятым, привести метки
   к словарю из `collect.transforms.genre_aliases`, исключить `TV Movie`, затем
   удалить метки, встречающиеся реже 25 раз. Строки без меток после фильтра
   удалить. Метки сортировать по Unicode и соединять строкой `", "`.
3. Сформировать `source_id` как
   `movie_ + SHA-256(NFC(strip(Title)) + U+001F + Release_Date + U+001F + lower(Original_Language))`.
   Полный хэш исключает зависимость от порядка строк и сохраняется одинаковым
   в обеих версиях.
4. Положить год из `Release_Date` в `topic=release_year:YYYY`. Одинаковый год
   целиком направляется в один split.
5. Выбрать вариант system prompt как
   `int(SHA-256(source_id), 16) mod len(system_prompts)`. В конфигурации пять
   вариантов, что превышает минимальное требование трёх.
6. До split удалить точные и near-duplicate описания, выполнить проверку PII и
   схемы. Отсортировать кандидатов по SHA-256 от `source_id`: v1 является
   префиксом v2, поэтому общие id и содержимое не меняются.
7. Получить около 3 000 чистых строк для v1 и не менее 6 000 для v2. Полный
   snapshot из 9 837 строк оставляет запас на фильтры. Версия не публикуется,
   если после очистки в ней меньше 1 000 строк или меньше 50 годов-групп.

Ожидаемый контракт исходной строки после преобразования содержит только
`id`, `topic`, `messages`; служебные `title`, `release_year`, язык и источник
используются для аудита до сериализации, но не попадают в `raw.jsonl`.

## Пример преобразования

Исходная строка из карточки набора:

```json
{"Release_Date":"2022-03-01","Title":"The Batman","Overview":"In his second year of fighting crime, Batman uncovers corruption in Gotham City that connects to his own family while facing a serial killer known as the Riddler.","Original_Language":"en","Genre":"Crime, Mystery, Thriller"}
```

Для строки хэшируется UTF-8 последовательность
`The Batman<U+001F>2022-03-01<U+001F>en`; SHA-256 равен
`a4a618a11088386ff9803a2f1f28a58490049f5e0ea4163ded3d336a33106b6c`.
Индекс system prompt для этого `source_id` равен 0. Результат преобразования:

```json
{"id":"movie_a4a618a11088386ff9803a2f1f28a58490049f5e0ea4163ded3d336a33106b6c","topic":"release_year:2022","messages":[{"role":"system","content":"Определи жанры фильма по его описанию. Ответь только списком жанров через запятую."},{"role":"user","content":"In his second year of fighting crime, Batman uncovers corruption in Gotham City that connects to his own family while facing a serial killer known as the Riddler."},{"role":"assistant","content":"детектив, криминал, триллер"}]}
```

Роли и порядок `system → user → assistant` неизменны.

## Версии и проверки перед публикацией

- v1: целевой объём около 3 000 чистых фильмов.
- v2: расширение минимум до 6 000 чистых фильмов; множество id v1 является
  подмножеством v2.
- В каждой версии после очистки должно остаться не менее 1 000 строк,
  не менее 50 значений `release_year` и не менее трёх system prompts.
- Для обеих версий вручную проверяется выборка исходная строка → chat-объект,
  корректность жанров, отсутствие названия в prompt и отсутствие сериалов или
  эпизодов.
- Между train и test не допускаются общие id, точные дубли и near-duplicates.

Фактический collect v1 от 2026-09-21 просмотрел все 9 837 CSV-строк. Причины
качества считаются независимо и потому могут пересекаться: найдено 9 строк без
описания, 11 без жанра, 10 с неверной датой, 10 без title/language, 214 с типом
`TV Movie` и 0 с неизвестными метками. После фильтров и двух аудиторских
исключений осталось 9 610 уникальных кандидатов; стабильным SHA-256-
ранжированием выбраны 3 000 строк v1. В результате 92 года, 35 языков, 18
канонических жанров, 2 502 multi-label примера и все 5 вариантов system prompt.
Полные распределения записаны в `metrics/collect.json`.

Контракт расширения проверен отдельным прогоном над тем же snapshot: v1 содержит
3 000 первых кандидатов, v2 — 6 000; все 3 000 id v1 входят в v2, а сообщения
общих записей совпадают побайтно.

## Гейт разнообразия для многометочной классификации

Общие проверки разнообразия ответов нельзя буквально переносить на эту
задачу. Здесь assistant выдаёт не свободный текст, а отсортированный набор из
18 канонических жанров. Одинаковые короткие ответы, например `драма` или
`комедия, мелодрама`, являются целевыми классами и закономерно повторяются.
Поэтому порог `max_duplicate_answer_share` установлен в 90%, а не в исходные
30%. Это не подгонка под один прогон: потолок допускает повторяемость конечного
словаря, но по-прежнему отвергает набор с несколькими почти константными
ответами. Проверки `min_answer_len_ratio=1.6` и
`max_same_length_share=25%` не ослаблялись: фактические значения 5,43 и 10,5%
имеют достаточный запас.

Допуск повторов компенсирован независимыми предметными гейтами:

- не менее 15 жанров из зафиксированного словаря;
- ни один жанр не встречается более чем в 50% строк;
- не менее 60% строк содержат несколько жанров;
- отношение p90/p10 длины входного description не ниже 2,5;
- сохраняются общие пороги: минимум 1 000 строк, 3 system prompts, 50 годов,
  не более 10% строк в одном году.

Для очищенной v1 из 2 998 строк фактически получены 18 жанров, крупнейший жанр
`драма` встречается в 37,3% строк, multi-label доля равна 83,4%, а длины
description p10/p50/p90 равны 126/259/495 символов (p90/p10 = 3,93). Таким
образом, каждый новый порог отделён от текущего значения заметным запасом и
проверяет самостоятельную ось качества. Метрика повторяющихся ответов равна
81,8%: это ожидаемое следствие конечных комбинаций меток, а не дублирование
входных описаний, которое отдельно удаляет стадия clean.

## Воспроизводимый ручной аудит 50 строк

Аудит проведён 2026-09-21. Seed — строка
`manual-audit-v1-2026-09-21`; выборка — первые 50 записей после сортировки по
`SHA-256(seed + id)`. Для каждой строки вручную сопоставлены исходные Title,
Overview и Genre с итоговыми user/assistant, проверены год, три роли, отсутствие
добавленного title/Genre в user prompt, канонизация и сортировка меток.

В первоначальной выборке найдены 2 ошибки типа произведения:

- `Donkey's Christmas Shrektacular`
  (`movie_8a6848fd219210debe1b13cd9604040c6399eb41d1e6d32c760f2e43f618b8f4`)
  является короткой праздничной программой, а не полнометражным фильмом;
  `Drama` и `Science Fiction` также не следуют из Overview. Карточка исключена
  целиком. Формат программы подтверждает
  [релиз Paramount](https://ir.paramount.com/news-releases/news-release-details/first-time-ever-all-four-films-biggest-animated-film-franchise).
- `Pixie Hollow Games`
  (`movie_34870477f31439c7c704739177d501ae9a7d635cf11727880daf030e1e591622`)
  — TV short, а не полнометражный фильм; карточка исключена целиком. Тип
  подтверждён в
  [технической карточке IMDb](https://www.imdb.com/title/tt1450334/technical/).

Оба стабильных id внесены в `collect.transforms.excluded_source_ids`, после
чего v1 пересобрана и та же процедура повторена на 50 строках итогового набора.
В повторной выборке критических ошибок не найдено. Спорный случай — метка
`Crime` у `S. Darko`: краткое Overview не раскрывает эту часть сюжета, но метка
не противоречит описанию и входит в исходную разметку, поэтому она сохранена.
Индивидуальные жанры не переписывались по субъективному впечатлению ревьюера:
при подтверждённом нарушении контракта исключается вся исходная запись.

## Нерешённые внешние действия

1. Получить у преподавателя подтверждение темы.
2. Карточка источника не содержит построчного `title_type`, runtime и подробной
   методики сбора. Поэтому `TV Movie` отсекается автоматически, а скрытые shorts
   выявляются воспроизводимым ручным аудитом; два найденных случая уже исключены.

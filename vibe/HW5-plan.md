# План выполнения ДЗ-5

## Задача

Интегрировать hw5-broken в накопительный проект ДЗ-1–5, исправить намеренные и скрытые дефекты, обучить два LoRA-адаптера Qwen3-0.6B на собственных данных жанров фильмов. Получить проверенные кривые, сравнение пяти вопросов, отчёт и воспроизводимый DVC DAG; сохранить историю коммитами и отправить её в GitHub.

Исходная папка hw4-broken отсутствует. Материалы course_tasks/hw5 однозначно соответствуют наличной hw5-broken; использовать её и удалить после интеграции. Исторические результаты ДЗ-1–4 сохранять с указанием старой модели. План хранится в репозитории: задача не связана с тикетом.

## Этапы

### Этап 1: Изучить требования и зафиксировать план

- Прочитать все три HTML в course_tasks/hw5, каждый исходник hw5-broken, действующие конфиги, DVC, тесты и README.
- Распределить ownership: агент training — train/data/runtime и тесты; compare — compare/plot и тесты; audit — независимая проверка без правок; основная агентка — интеграция и запуск.
- Сохранить план и трекер; зафиксировать материалы задания коммитом.
- Проверка: git status, список файлов и исходный SHA-256 tests/check.sh.

### Этап 2: Интегрировать конфигурацию и исправленный код

- Добавить src/train.py, data.py, runtime.py, compare.py, plot.py с исправлениями val, lr, freeze14, portable tokenizer, seed и скрытых ошибок накопления/метрик.
- Сохранить src/config.py и lora.configs прежних ДЗ; дополнить params.yaml, Makefile, dvc.yaml и .gitignore.
- Перенести проверку ДЗ-4 в check_hw4.sh, исходную ДЗ-5 в check.sh без изменения байтов; предусмотреть все пять ДЗ в check-all.
- Сменить общую модель на Qwen3-0.6B; зафиксировать 5 prompts из val собственной темы.
- Добавить DVC train_all/train_freeze/plot/compare с зависимостями данных, кода, lock и конфигурации.
- После сохранения исходников удалить hw5-broken. Коммит интеграции.
- Проверка: uv sync --locked, unittest, bash -n tests/*.sh, dvc dag, git diff --check.

### Этап 3: Написать регрессионные тесты

- Проверить хвост grad_accum, токен-взвешенные loss/градиенты, seed, freeze layers, безопасное чтение PT, fingerprint данных, одинаковые train/inference prompts и greedy, переносимость, графики.
- Проверка: uv run python -m unittest discover -s tests -p 'test_*.py'.

### Этап 4: Воспроизвести данные и обучить оба варианта

- Пересчитать tokenize своих 4800 train / 599 val под выбранную модель.
- Сделать smoke 5 шагов с отдельным out, затем полный epoch без max_steps для all_layers и freeze14.
- Пересчитать DVC DAG и прочитать конечные JSON; построить curves.png и compare.md.
- Зафиксировать реальные параметры, loss, время, память, размер адаптера и входной fingerprint.
- Проверка: dvc status, полный набор make check-all, совпадение двух 3-step smoke и офлайн ответов.

### Этап 5: Независимая повторная прожарка

- Попросить audit заново проверить итоговые файлы, результаты и соответствие каждому условию, включая скрытые риски и сохранение прошлых ДЗ.
- Исправить найденное; изменения обучающего кода или конфига требуют нового полного обучения.
- Проверка: адресные regression tests и необходимые повторные проверки. Не менять приёмочный скрипт ради зелёного результата.

### Этап 6: Документация, итоговый коммит и push

- Дополнить docs/defects.md пятью разделами ДЗ-5 с числами и дополнительными дефектами; README — архитектурой, запуском, ограничениями и результатами.
- Записать настоящую терминальную сессию make check-all, преобразовать её в MP4, проверить декодированные кадры и сохранить исходные события; обновить сценарий и план-трекер.
- Зафиксировать docs/curves.png, docs/compare.md, docs/checks.mp4, docs/checks-session.jsonl, DVC lock и тексты; не коммитить модели, PT, JSON обучения.
- Проверка: git diff --check, git status, fingerprints, гигиена tracked файлов.
- Сделать финальный коммит, git push origin main, проверить совпадение HEAD и origin/main.

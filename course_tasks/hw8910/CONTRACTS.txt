ДЗ 8+9+10: контракты трёх функций
Python 3.12, стандартная библиотека. Быстрые тесты не требуют MLflow, Prefect или модели.

1. cache_key(data_path, config) -> строка SHA-256, 64 строчных hex-символа.
Учитывает байты входного файла и все поля config. Одинаковые байты в разных путях
дают одинаковый ключ. Порядок ключей dict значения не имеет. Изменение данных,
ревизии токенизатора, шаблона, max_length или версии кода подготовки меняет ключ.
config в реальном потоке должен содержать эти поля, а не произвольную константу.
Рекомендуемый способ: SHA-256 канонического JSON {data_sha256, config}.
Канонический JSON: sort_keys=True, separators=(',', ':'), ensure_ascii=False,
allow_nan=False, кодировка UTF-8. Название файла и mtime не заменяют хеш содержимого.

2. validate_release(manifest, report) -> None или ValueError.
manifest: schema_version (именно int 1), непустые строки model_id и artifact_uri;
model_sha256, protocol_sha256, golden_sha256, runtime_sha256 (SHA-256, lowercase);
непустой runtime dict. Пересчитайте runtime_sha256 из канонического runtime.
report: status == 'complete', passed is True (не строка), непустой evaluation_run_id;
model_id и все четыре хеша совпадают с manifest. metrics содержит accuracy и
format_rate: конечные int/float от 0 до 1 включительно, bool и строки запрещены.
Отсутствие обязательного поля, несовместимость, NaN/Inf и отказ — ValueError.
Дополнительные поля разрешены. Эти проверки не заменяют quality_gate из ДЗ 6+7.

runtime фиксирует фактические base_revision, tokenizer_sha256, template_sha256,
generation (включая системную инструкцию или её хеш, do_sample, seed при sampling,
max_new_tokens, enable_thinking) и dtype. Используйте тот же runtime для оценки
и API. Если конфигурация изменилась, нужен новый отчёт, а не правка его хеша.
model_sha256 вычисляйте по закреплённому списку файлов артефакта: относительный
путь → SHA-256 файла, затем SHA-256 канонического JSON этого словаря. Для адаптера
список включает веса и adapter_config; базу закрепите точной revision.
Перед публикацией и загрузкой пересчитайте хеши реальных файлов отдельно:
validate_release сверяет метаданные, но сама не скачивает и не проверяет веса.

Отчёт report создаёт ваша обвязка после вызова quality_gate ДЗ 6+7, не человек.
Она сохраняет ссылку/путь и SHA-256 полных baseline/candidate-eval и сырых ответов,
переносит статус, метрики и идентификаторы из этого результата. Обёртка не разрешает
подменить решение по одному val_loss. Отклонённые/неполные отчёты тоже сохраняются.
В examples/ только синтетические контракты для тестов: они не доказывают качество.

3. publish(manifest, report, target: Path) -> None.
Сначала validate_release. Далее запись JSON manifest во временный файл рядом с
целевым, flush/fsync и os.replace. При отказе целевой файл побайтно неизменен.
При ошибке замены прежний файл остаётся, исключение выходит наружу, временный файл
удаляется. Повтор одинакового выпуска даёт те же байты без дубликатов.
В этой работе один писатель. Атомарная замена не решает конкуренцию писателей
и не означает, что модель уже перезагружена в API. accepted.json — локальный
указатель; это не операция присвоения MLflow Registry alias.

# MLOps: накопительный проект ДЗ-1 — ДЗ-5

Репозиторий объединяет пять домашних работ: воспроизводимый инференс Qwen3,
анализ устройства модели, DVC-пайплайн датасета для многометочной классификации
жанров фильма по текстовому описанию и препроцессинг этого датасета для
обучения и LoRA-адаптеры для классификации жанров. Тема датасета согласована с преподавателем.

## ДЗ 1 — Окружение, первый инференс Qwen3, бенчмарк машины

## Что нужно сделать

1. Поднять окружение: `uv sync`, закоммитить `uv.lock`.
2. Заполнить `TODO` в коде.
3. **Найти и исправить четыре намеренных дефекта.** Симптомы описаны
   в задании; конкретные строки не указаны — искать нужно самим.
4. Прогнать `make bench`, определить свой профиль железа по таблице курса
   и записать выбранную модель в `params.yaml`.
5. Написать `docs/hardware.md`: результаты замера **и разбор каждого
   найденного дефекта** — в чём был, как проявлялся, как исправлен.
   Простое «починил» не засчитывается.
6. Согласовать с преподавателем тему своего датасета — тема согласована.

## Запуск

```bash
uv sync
make generate     # генерация
make bench        # замеры
make check-hw1    # самопроверка ДЗ-1
```

## Подсказка по железу

Модель выбирается **только** через `params.yaml`. Если ваша машина
не тянет базовую — возьмите `HuggingFaceTB/SmolLM2-135M-Instruct`.
Оценивается пайплайн, а не качество модели.

## ДЗ 3 — Датасет жанров фильмов и DVC

Датасет построен из зафиксированной ревизии
[`Pablinho/movies-dataset`](https://huggingface.co/datasets/Pablinho/movies-dataset)
с лицензией CC0-1.0. Название фильма исключено из пользовательского prompt:
модель классифицирует только описание. Пайплайн состоит из пяти стадий:

```text
collect → clean → diversity → split → contamination
```

Доступны две воспроизводимые версии данных:

| Версия | Git-тег | Raw | Clean | Train / val / test |
|---|---|---:|---:|---:|
| v1 | `data-v1` | 3 000 | 2 998 | 2 397 / 300 / 301 |
| v2 | `data-v2` | 6 000 | 5 998 | 4 800 / 599 / 599 |

Групповой split не разделяет фильмы одного года между выборками. Для активной
v2 пересечения train/test по ID, нормализованному тексту, году и near-duplicate
равны нулю.

### Воспроизведение и проверки

```bash
uv sync
uv run dvc pull        # если восстановлен локальный remote в dvc_remote/ репозитория
make repro             # воспроизвести весь DVC DAG
make check-hw3         # восемь проверок ДЗ-3
make check-hw1         # регрессия ДЗ-1
make check-hw2         # регрессия ДЗ-2
make check-hw4         # девять разделов проверки ДЗ-4
make check-all         # полный набор ДЗ-1–5
```

Переключение версий выполняется только штатными целями:

```bash
make v1
make v2
uv run dvc metrics diff data-v1 data-v2
```

Данные `data/`, исходный snapshot и DVC remote не хранятся в Git. В Git
остаются код, конфигурация, `dvc.lock`, DVC pointer и небольшие JSON-метрики.
Настроенный DVC remote `local` содержит URL `../dvc_remote` в `.dvc/config`.
DVC разрешает его относительно каталога `.dvc`, поэтому фактический путь —
`<repo>/dvc_remote`, внутри репозитория. Эта папка не публикуется на GitHub.
Для `dvc pull` в новом клоне нужно отдельно передать содержимое remote в
`<clone>/dvc_remote`. Если копия remote расположена в другом месте, можно
указать её абсолютный путь только для своего клона:

```bash
uv run dvc remote modify --local local url /absolute/path/to/dvc_remote
uv run dvc pull
```

Без remote исходный CSV можно скачать по зафиксированному
URL из `params.yaml`: `make bootstrap-source` сверит SHA-256 и заполнит
локальный DVC-кэш. Затем `make repro` пересчитает все стадии. Команда требует
доступа к публичному Hugging Face snapshot и для ДЗ-4 — к токенизатору Qwen3.

Документация ДЗ-3:

- [datasheet](docs/datasheet.md) — источник, лицензия, преобразования, качество
  и ограничения;
- [разбор дефектов](docs/defects.md) — пять намеренных дефектов и подтверждение
  исправлений;
- [сравнение v1 и v2](docs/metrics-diff.md) — фактический DVC metrics diff;
- [сценарий скринкаста](docs/screencast.md) — порядок демонстрации результата.

Полная формулировка находится в `course_tasks/hw3/2-zadanie-dz3.html`.

## ДЗ 4 — Токенизация и маска обучающего сигнала

Вход стадии — **свои** `data/train.jsonl` и `data/val.jsonl` из стадии
`split` ДЗ-3, а не преподавательский parquet. Новая стадия `tokenize`
добавлена в общий DVC DAG после `split`:

```text
collect → clean → diversity → split → tokenize
                                 └────→ contamination
```

Исторический результат ДЗ-4 получен на `Qwen/Qwen3-1.7B`. Для ДЗ-5
общая модель переключена на `Qwen/Qwen3-0.6B`, свои train/val повторно
токенизированы; количества и длины токенов совпали. Train и
inference строят строки через один `src/prompt.py` и
`apply_chat_template` с `enable_thinking=false`. В `labels` остаются только
токены ответа и EOS; промпт и padding имеют значение `-100`. Коллатор
дополняет батч слева, выставляя `attention_mask=0` на padding.

На версии данных v2 лимит `max_seq_len=320` выбран по измеренным длинам:

| Split | Строк сохранено | p50 / p90 / p99 / max | Усечено | Всего токенов | Под лоссом |
|---|---:|---:|---:|---:|---:|
| train | 4 800 / 4 800 | 113 / 162 / 235 / 300 | 0 (0%) | 576 023 | 51 919 |
| val | 599 / 599 | 119 / 167 / 231 / 273 | 0 (0%) | 74 255 | 6 411 |

Прогноз для трёх эпох — **11,24 ч** при 42,69 токена/с. Эта скорость измерена
в ДЗ-1 на генерации, поэтому прогноз служит оптимистичной границей, а не
замером обучения с backward и шагом оптимизатора. Packing отключён: без
блочной маски внимания соседние примеры в одном бине влияли бы друг на друга.

### Воспроизведение и проверка

```bash
uv sync --locked
make bootstrap-source       # в новом клоне без локального DVC remote
make repro                  # воспроизвести весь DAG, включая tokenize
make tokenize               # необязательно: повторить только стадию токенизации
make check-hw4              # девять разделов проверки ДЗ-4
make check-all              # регрессия всех пяти работ
```

Стадия `split` внутри `make repro` создаст входные train/val. Если восстановлен
remote в `<repo>/dvc_remote` или перенастроен его локальный URL, вместо
`make bootstrap-source` можно выполнить `uv run dvc pull`.

Тензоры `data/tokenized/{train,val}.pt` и остальные файлы `data/` находятся
под DVC и не отслеживаются Git. Небольшие
[`metrics/tokenize.json`](metrics/tokenize.json) и
[`docs/tokenize_report.md`](docs/tokenize_report.md) сохранены в репозитории.
Разбор четырёх исправленных дефектов находится в
[`docs/defects.md`](docs/defects.md); сценарий записи девяти проверок — в
[`docs/screencast.md`](docs/screencast.md). Исходный проверочный скрипт
перенесён без изменений, его отпечаток SHA-256 начинается с
`f2002c8c9519`.

Материалы задания — `course_tasks/hw4/`. Преподавательский `make sample`
использует внешний parquet курса и не требуется при работе с этим
репозиторием.

## ДЗ 5 — Обучение LoRA на жанрах фильмов

Каркас `hw5-broken` интегрирован в общие `src/`, `tests/`, конфигурацию и
DVC; исходная папка удалена. План и задачи:
[vibe/HW5-plan.md](vibe/HW5-plan.md),
[трекер](vibe/HW5-plan-track.md). Материалы задания — `course_tasks/hw5/`.

Активная модель — `Qwen/Qwen3-0.6B`, устройство `auto`, bf16. Исторические
отчёты ДЗ-1/2 относятся к указанной в них модели и условиям замера.
Используются все собственные 4 800 train и 599 val версии v2. За одну эпоху
выполняется 600 шагов: batch=8, grad_accum=1, eval_batch_size=8, lr=2e-4, seed=42.
LoRA r=8, alpha=16 навешивается на семь проекций attention/MLP.
`all_layers` обучает адаптеры на слоях 0–27, `freeze14` — на 14–27.

```text
collect → clean → diversity → split → tokenize → train_all → compare
                              │          └────→ train_freeze
                              └→ contamination
                              train_all + train_freeze → plot
```

```bash
uv sync --locked
make bootstrap-source          # в новом клоне без DVC remote
make repro                     # весь DAG, включая оба полных обучения
# Если данные уже готовы:
make train                     # all_layers, затем freeze14, затем график
make compare                   # пять фиксированных описаний из своего val
make check                     # девять проверок ДЗ-5
uv run python scripts/check_hw5_artifacts.py  # свежесть и полнота артефактов
make check-hw4                 # прежняя проверка токенизации
make check-all                 # проверки ДЗ-1–5
uv run python -m unittest discover -s tests -p 'test_*.py'
```

Пробное обучение пишет результаты отдельно и не подменяет полный прогон:

```bash
uv run python -m src.train --variant all_layers --max-steps 5 --val-limit 8 --out /tmp/mlops-hw5-smoke
```

На CPU установите `model.dtype: float32`; полный прогон будет существенно
медленнее. Изменение модели требует повторной токенизации. После изменения
обучающего кода, конфигурации, lock или данных нужно пересчитать обучение:
проверки сверяют отпечатки реальных входов и версий зависимостей.

Val loss считается по токенам ответа на шаге 0, каждые 10 шагов и в конце.
Градиенты также нормируются по токенам полного накопленного батча; короткий
хвост эпохи не теряется. Для Qwen3 `lm_head` вычисляет логиты только для
последних `K+1` позиций, где `K` — длина хвоста от первой обучаемой метки
в батче до конца последовательности. Дополнительная позиция перед ответом
сохраняет лосс первого токена при causal shift. Transformer получает полный
контекст, маски и знаменатель лосса остаются прежними; сокращается размер
тензора логитов по всему словарю. Это уменьшает расход памяти при
`eval_batch_size=8`.
Пик MPS измеряется с интервалом 10 мс, RSS сохранён
отдельно; короткие всплески между замерами могут остаться незамеченными.

Результаты: [кривые](docs/curves.png), [пять сравнений](docs/compare.md),
[разбор дефектов](docs/defects.md), [сценарий видео](docs/screencast.md).
Сохранены [видео реальной терминальной сессии](docs/checks.mp4) с
`make check-all` и [исходная запись PTY](docs/checks-session.jsonl).
В кадре — девять проверок ДЗ-5, финальная строка успеха и отпечаток
**06a02208c1f0**. Паузы сокращены с явной подписью; аудио нет.
Пять вопросов демонстрируют подключение адаптера, а статистическую оценку
точности классификации по ним делать нельзя.

Адаптер содержит LoRA-веса, токенизатор, chat template и метаданные обучения.
Для офлайн загрузки базовые веса должны быть заранее в Hugging Face cache:
проверка переносит только папку адаптера, отключает сеть и сравнивает пять
ответов дословно. База не входит в маленький адаптер.

`models/`, тензоры и JSON обучения/сравнения не попадают в Git. Исторические
небольшие метрики ДЗ-3/4 остаются в Git по условиям этих работ; это адаптация
накопительного проекта к правилу ДЗ-5 о новых генерируемых метриках.
DVC-кэш и локальный remote также не публикуются на GitHub. В новом клоне
`make bootstrap-source && make repro` восстанавливает данные и обучает
адаптеры; для загрузки модели нужен доступ к Hugging Face.

`make clean-training` удаляет только адаптеры и результаты ДЗ-5. `make clean`
также очищает временные результаты предыдущих работ; `make distclean` удаляет
ещё и `.venv`. Исходный `tests/check.sh` ДЗ-5 сохранён без правок: SHA-256
начинается с **06a02208c1f0**. Проверка ДЗ-4 перенесена в `check_hw4.sh`
(отпечаток **f2002c8c9519**). Дополнительная проверка закрывает пропуски
приёмочного скрипта; видео проверки и исходная запись событий приложены
в `docs/`.
